# Desktop shell: Home and project tabs

Implemented October 2, 2026. The outer project tab model is separate from the existing conversation/document `WorkspaceTab` model.

## User behavior

Home is permanent. Projects open once per window, append at the right, can be reordered by drag or the accessible context menu, and overflow horizontally. The project picker searches names and paths and reuses the existing connection flows. Closing an active project selects its left neighbor; closing Home with Command-W closes the window. Closing views never calls provider stop/disconnect or removes project membership.

Home provides All projects, Recents (user openings), Search, Attention and Imported Activity, plus Connections and Settings. Grid/list views use static isometric rectangles and existing usage/uncertainty semantics. The shell follows macOS appearance; conversation panels remain light.

Shortcuts: Command-T picker, Command-W close project, Control-Tab / Control-Shift-Tab cycle, Command-1 Home, Command-2 through 9 project tabs. Escape remains owned by menus, previews and workspace overlays.

## Ownership and restoration

`LibraryModel` has one application service owner and window presentation facades. The owner installs provider callbacks once, owns execution, session discovery, shared observation/indexing, drafts and inbox storage, and runs the existing discovery/usage schedules. Each facade has independent navigation, project selection overlays, transcript selection, spatial UI and generation checks. `ProjectRepository` shares persistent membership/workspaces while `ProjectModel` isolates selection, file navigation and expanded folders.

`ProjectTabStore` stores stable project IDs, order, Home preferences, opening dates and lightweight workspace/bookmark snapshots. `WorkspaceNavigation` persists outer and inner tabs in window namespaces with a 200ms debounce. Legacy layout/document preferences migrate into the first window. Safe development shutdown flushes every registered window. Missing folders keep their tab and provide Retry/Locate actions.

Each window mounts one `SpatialSceneView`. Camera poses are values; no scene is retained per tab. The fixed floor, walls, leisure assets and empty desk nodes are reused when switching projects. Furniture resets to baked transforms before applying the destination project's edits. Home and inactive/occluded windows stop rendering. Project projection is restricted to that project, and hidden histories are not loaded.

Conversation follow/anchor state and read depth are saved per conversation; inbox list/detail anchors reopen with bounded queries around the stored identity. Drafts remain keyed by the existing conversation identity. Project snapshots also retain panels, widths, roster disclosures and selected tools/documents.

## Verification

See `ProjectTabTests`, `DesktopShellRenderingTests`, and the navigation, scrolling, execution, observation, inbox and office regression suites. Tests use fixtures only; provider calls are rejected by the shell fixture transport.

Native checks cover Home, project search, opening and closing tabs with Command-W, Command-1, and a second independently initialized window. The 20-tab fixture retains 20,000 messages in shared data, checks exactly one native renderer across switches, and checks Home rendering is stopped. It reports switch-to-layout timings (including a 20ms scheduling wait) and resident memory after each round; these are not GPU frame-rate measurements or a 60 FPS guarantee.

Final optimized acceptance run: 114 tests in 16 suites passed (34.793 seconds). This includes exact native history-anchor restoration after unmount/remount, streaming and manual scrolling, execution, observation, naming, inbox paging, fixed office capacity, furniture editing and navigation. `git diff --check` passed.

On this Mac at 2× backing scale, the 20-tab/20,000-message fixture measured 21.56ms median, 49.21ms p95, and 68.35ms maximum switch-to-layout time, including the 20ms scheduling wait. Resident memory was 1,230,995,456 bytes after the first pass and 1,231,011,840 after the second: 16KiB growth. The model-only 1,000-switch test took 9.32ms. These establish bounded fixture behavior, not a universal latency or memory guarantee; some switches still exceed one display frame.

Full VoiceOver narration, sustained GPU frame pacing with populated offices, and exhaustive multiwindow restoration after an operating-system session restore were not measured in this change. Accessibility labels and independent window presentation are covered by implementation/native checks; light/dark Home snapshots are generated by the rendering fixture. No paid agent turns were started.

## Tab readability and warm Home transitions

Overflowing project names scroll inside the fixed title viewport, with pauses and a slow reversing motion. Short names remain still. Reduced Motion or an inactive window disables motion; the full name remains in the tooltip and accessibility label. No project name is shortened in storage.

Home remains mounted so its cards and scroll position can appear without reconstructing the library. Summary refresh notifications are coalesced outside the navigation action. Entering Home suspends the office without reframing its hidden camera or requesting meadow coverage, and hidden scene layout skips camera work. The native fixture records warm Home switch/layout separately and verifies that its camera pose stays unchanged.

Follow-up verification: 26 tests across desktop tabs, native shell rendering, workspace navigation and shared offices passed; the preceding run also passed conversation autoscroll. Warm Home synchronous selection/layout measured 19.85ms (earlier runs 14.75–16.24ms), with the hidden camera unchanged. The 20-tab fixture still recorded 24.57ms median, 77.87ms p95 and an 898ms maximum including its 20ms scheduling wait; project opening is not universally instantaneous and that slow path remains a limitation. Repeated-pass resident memory grew 48KiB. Home summaries now yield between sessions, cancel when hidden, and reuse the same reported-state projection logic.

## Project-to-project switching follow-up

The window retains up to 24 lightweight project roster projections. View evaluation no longer synchronously projects a newly selected project or repeats that work while Home is hidden. A cached roster appears immediately; fresh observations reconcile after selection with cancellation on a subsequent switch. Home does not observe individual project-tab identities while hidden. The former portfolio transition animation is removed.

Furniture templates prepare once on a worker, using the application/SwiftPM resource bundle published before work starts. The native surface retains only the latest request while awaiting preparation; it cannot display an obsolete destination after rapid switching. Live scene mutation remains on the main actor. Meadow coverage is not recalculated before the destination camera is restored, and identical camera coverage is reused.

A bounded pool reuses avatar rigs and furniture across project switches. Rebinding stops prior travel/animation, restores the seated baseline, replaces the leisure controller, removes old plan controls and updates agent/monitor hit identities. There remains one renderer per window and at most 34 retained office workstations across the active set and reusable pool. Static status label geometry is capped at 32 entries; title images use a 16 MiB, 128-entry cache with independent per-avatar scrolling materials.

Verification: 56 optimized regressions across 10 suites passed, including actual furniture loading, stale asset-request cancellation, fixed capacity, editor, leisure, meadow, title scrolling and navigation. With 34 visible avatars, warm scene reconciliation improved from 87.58ms median / 89.87ms maximum to 3.72ms median / 3.90ms maximum in the final run (2.58ms / 2.67ms in the preceding run). The 20-tab native return-to-open-project fixture measured 29.55ms median / 35.45ms maximum in the final run, including its deliberate 20ms scheduling wait. Settling callbacks are coalesced into one refresh instead of one refresh per avatar. These supersede the preceding slow-path measurements. They measure scene reconciliation and native layout, not GPU presentation latency or a guarantee for every hardware/load combination. No paid agent turns were used.
